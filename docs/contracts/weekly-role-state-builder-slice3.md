# Slice 3: injected weekly role-state constructor

This additive, pure constructor implements the existing `WeeklyRoleStateV1` vocabulary. It accepts one `PlayerTeamAllocationHandoffV1`, its mandatory exact raw-byte-pinned Slice 2 companion, an explicit source-native subject selector, and a new artifact identity. It neither accesses the filesystem/network nor invokes the legacy scorer or Slice 2 production adapter. This slice runs only fictional synthetic fixtures. It provides no source admission, player-purpose acceptance, upstream byte authentication, consumer activation, or real-player evaluation.

## Input and dependency boundary

The handoff must validate under the merged Slice 1 validator and its JCS content hash must match its exact reference. The companion must match its raw-byte SHA-256/size, embed precisely that handoff reference, declare its complete source/native row population, and retain the pinned support-file declarations. The constructor checks selected row identity/count/evidence locators against the handoff and companion. It returns an explicit `binding` with the handoff reference, companion raw-byte pin, support basis and purpose alongside the state; the existing state schema does not embed the companion pin. Retain the returned binding with any future output. These local checks **do not authenticate** missing external support bytes or assert provider authorship. A later integration must verify the upstream raw files against the reviewed retained binding and resolve external dependencies before real use. A newly supplied companion pin alone does not qualify an upstream source.

An observed identified row requires the companion's Data-owned `carry_share_all_team_carries`, `target_share_credited_team_targets`, and `carries_plus_targets` objects. The constructor preserves their exact numerator, denominator, value, status and reason and rejects absent or contradictory objects. It does not derive either Data-owned share from handoff counts. All-team carries include QB and non-skill work; credited team targets are distinct from pass attempts. QB pass-attempt share and conservatively qualified RB-room carry share use the existing handoff counts and documented Slice 1 definitions. No universal opportunity metric exists.

## Output and atomic claims

One segment per matched source row retains source-observed game, team, opponent, position, observed/null counts, and evidence references. RB, WR, TE and QB use their explicit Slice 1 branches. The output sets `comparison: null`, `teamstate: []`, and `consumerActivation: none`; scoring-area and advanced data remain reserved. Handoff coverage, finality, correction, evidence cutoff and purpose carry through without upgrading the source. Fixture evidence remains fixture, and ROP purpose is accepted only with the explicit accepted ROP purpose in a valid candidate; candidate lifecycle alone does not upgrade evidence. Identical inputs and artifact identity yield identical content digest and output.

The constructor emits only the merged rules: recorded rushing work, recorded receiving opportunity, observed receiving involvement, QB passing/rushing work, unique qualified RB carry leadership, and strict majority of qualified RB carries. Counts of zero can yield `not_supported`; null counts yield `insufficient`. It uses the merged conservative RB-room rule: complete population, reconciled team carries, observed zero residual, resolved row identities, recognized positions and observed row carries. An unknown-position row with zero carries leaves room *membership* unresolved even though it does not alter the arithmetic attribution of recorded RB carries; loosening this rule would require separate review. No narrow archetype, role score, fantasy-point input or future-volume claim is generated.

## Interface questions before any real evaluation

- The Slice 1 state does not itself bind the Slice 2 companion pin. Future persistence/presentation must carry and verify the returned binding together with the state, or obtain a reviewed contract extension.
- The unattributed raw observation has no Data-derived share object. The constructor preserves it in the handoff/companion but refuses to emit a row state requiring that unavailable Data object; a distinct reviewed policy is needed if anonymous row states become useful.
- A resolved subject absent from qualified source rows needs its own independent identity/population evidence. The constructor rejects an inferred resolved absence. A generic unresolved absent state remains available without inventing zero work.
- This slice does not implement prior-week comparison, optional Teamstate attachment, source authentication or operational purpose acceptance. Those need separate authorization and review.
